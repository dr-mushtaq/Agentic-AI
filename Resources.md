The Difference
Say your task is: “Research the top 5 electric bike brands and tell me which one to buy under $1,500.”

Normal prompt AI: You type the question into ChatGPT. It answers from memory, some of it outdated, none of it verified against current prices. You get five paragraphs of plausible-sounding text, then open six browser tabs to check if any of it’s still true, copy specs into a doc yourself, and repeat the prompt a few times to catch what it missed. Forty minutes later, you have a rough answer you still don’t fully trust.

Agentic AI: You give the same task to an agent with tools attached. It plans the research (which brands, which retailer sites for current prices), searches the web, extracts specs into a table, cross-checks price against three sources, flags the one listing that looks stale, writes a one-page recommendation with sources cited, and re-reads its own draft against your budget before handing it back. You review once. Ten minutes, most of it just reading the finished output.

Same question, often the same model underneath.

The difference is the loop: plan, act, observe, correct, finish. That loop is what this newsletter teaches you to build.

# Week 2: Tools
An agent without tools is just a chatbot with extra steps.

This week is about function calling: how an LLM decides which tool to call and with what parameters.

Week 2: Function-Calling and Data Extraction with LLMs

Free short course from DeepLearning.AI. Teaches how LLMs generate structured tool calls and use them to extend a chatbot into something that can take real actions.

[Link:](https://www.deeplearning.ai/courses/function-calling-and-data-extraction-with-llms) 

Time: About 1.5 hours

What this teaches you:

How function calling works under the hood: how an LLM reads a tool description and decides when to use it

How to write function definitions the model can reliably understand and call correctly

How to handle multiple function calls, including parallel calls and nested calls where one tool’s output feeds another

How to convert an existing OpenAPI spec into functions your LLM can call directly, so you’re not writing every tool wrapper by hand

How to pull structured data (names, dates, categories) out of messy natural language input

A full worked project: turning customer service transcripts into SQL calls that write straight to a database

Do this: Build one tool-using mini-agent by the end of this week. Something small, a weather lookup agent is fine.

# Week 3: Memory
Right now, your agent forgets everything the second the session ends.

Week 3 fixes that with memory architecture:

What to store, what to retrieve, and how an agent updates its own knowledge over time.

Week 3: Agent Memory, Building Memory-Aware Agents

Free short course from DeepLearning.AI, built with Oracle. Teaches memory-first architecture, a Memory Manager, and write-back loops so your agent improves across sessions instead of starting from zero every time.

[Link](https://www.deeplearning.ai/courses/function-calling-and-data-extraction-with-llms)

Time: About 2 hours

Why stateless agents break down on any task longer than one session, and what “memory-first architecture” means in practice

How to treat your agent’s tools as their own kind of memory, retrieved by semantic search instead of dumping every tool into the prompt

How to build extraction and consolidation pipelines that turn raw conversation into structured facts your agent can reuse later

How to set up write-back loops so the agent updates its own memory on its own, without you manually editing anything

How to assemble a full Memory Aware Agent that loads its prior context the moment a new session starts

Week 4: Multi-agent systems
One agent hits a ceiling fast.

Real workflows split into roles: A planner, a researcher, a writer, a reviewer, each with a narrow job, talking to each other.

# Week 4: Multi AI Agent Systems with crewAI

Free short course from DeepLearning.AI Teaches how to design a team of role-based agents that collaborate on one task, using natural language to define each agent’s job.

[Link](https://www.deeplearning.ai/courses/multi-ai-agent-systems-with-crewai)

Time: About 2 hours

What this teaches you:

How to assign each agent a specific role, goal, and backstory, so it stays focused instead of trying to do everything at once

How to give agents short-term, long-term, and shared memory so a team can actually collaborate instead of working in isolation

How to hand out pre-built and custom tools to specific agents, matched to the job each one does

How to set guardrails that stop an agent team from hallucinating, looping forever, or silently failing mid-task

The difference between running agents in series, in parallel, and hierarchically, and when to use each

Six full worked examples: resume tailoring, technical writing, customer support, outreach campaigns, event planning, and financial analysis, all built as agent crews

Do this: Turn your single mini-agent into a small team of two or three agents, each with a distinct role.

# Week 5: Evals
This is the week almost everyone skips, and it’s the reason most homemade agents quietly fail in production.
You need a way to measure whether your agent is getting better or just looking busy.

Week 5: Evaluating AI Agents

Free short course from DeepLearning. AI, built with Arize AI. Teaches observability, tracing agent steps, and choosing the right evaluator (code-based vs. LLM-as-a-judge) for each part of your agent.

[Link](https://www.deeplearning.ai/courses/evaluating-ai-agents)

Time: About 1.5 hours

What this teaches you:

Why evaluating an agent is different from traditional software testing, and why “it worked once” isn’t proof of anything

How to break an agent down into its actual components (routers, skills, memory) so you evaluate each part instead of just the final answer

How to add observability: collecting and visualizing the trace of every step your agent took, so failures stop being a mystery

How to pick the right evaluator for each piece: code-based checks, LLM-as-a-judge, or human review, and when each one applies

How to compute a convergence score, so you can tell if your agent is solving a task efficiently or just eventually stumbling into the right answer

How to run structured experiments that isolate whether a fix belongs in the prompt, the model, or the agent’s logic

Do this: Set up one eval for your Week 4 multi-agent team. Even a simple pass/fail check counts.
